What it is

A one-page departures board. You paste a hackathon deadline; the page finds the moment it means, shows it in your time zone, warns about the daylight-saving gap between regions, and plans the shipping steps backwards. Everything runs in the browser; nothing is stored except your last plan in this browser's local storage.

One action, end to end: pasting a deadline

1 · Reading the text — src/parse.js, search export function parseDeadline. Finds the date, time and zone word in what you pasted; resolveDeadline turns them into one exact moment and builds the "Read as" line.
2 · Time-zone maths — src/clock.js, search export function wallToInstant and export function dstTrap. Uses the browser's own Intl rules to get each city's offset on that date, and compares this week's gap with the usual one.
3 · The board — src/app.js, search function render(. Every second it redraws the countdown, build time left, runway and statuses from buildPlan and statusAt in src/plan.js.

A practice to reuse

The PRD wrote down observable results before any code ("Oct 26, 2026 5:00pm EDT seen from Madrid shows 22:00 and a 5 h vs usual 6 h warning"). Those sentences became the tests in tests/core.test.js. When a browser check showed a misleading warning for "EDT" in November, the fix was judged against the same written expectations, and a test was added. Writing the expected screen result first makes an agent's work checkable on any project.
